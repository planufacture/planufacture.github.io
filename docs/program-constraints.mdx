# Program Constraints

The **Program Constraints** module manages compatibility rules - which values of a SKU
attribute may share a program cycle. For example, a rule might say two flavours are
compatible on the same cycle but an allergen-containing product is not.

![Program Constraints](/img/screenshots/program-constraints-overview.png)

## Overview

- **Rule list** showing each rule, the attribute it keys on, and its values
- **Add Constraint** button to create one
- **Detail page** to edit the rule's allowed pairs or delete it

### Rules Table Columns

- **Rule Name**: Unique name for the rule
- **Rule Description**: Optional free-text description
- **Attribute**: The SKU attribute the rule compares
- **Values**: The attribute values covered by the rule
- **Actions**: Show icon opens the rule detail page

## Rule Fields

- **Rule Name**: Required name
- **Description**: Optional description
- **Attribute**: The SKU attribute whose values are checked for compatibility. Choose an
  attribute and click **Apply** - the values it actually takes across the catalogue are
  discovered and used to build the matrix
- **Allowed Pairs**: A checkbox matrix pairing every discovered value against every other
  value. Tick a pair to allow those two values to share a cycle; a pair left unticked may
  not share one

## Editing Allowed Pairs

![Add Program Constraint](/img/screenshots/program-constraints-add.png)

The **Allowed Pairs** matrix lists every unordered value pair - since pairs are unordered,
only the upper triangle is tickable. Tick the pairs that are compatible. Pairs can also be
imported from / exported to a spreadsheet - values that the attribute doesn't actually take
are discarded and reported after import.

## How Constraints Relate to Programs

- **Programs** ([Programs](programs)) define the cycles themselves
- A **process** of type **Program** runs a chosen program
- Compatibility rules constrain which products (by attribute value) the scheduler may place
  in the same cycle

## Common Workflows

### Creating a Compatibility Rule
1. Click **Add Constraint**
2. Enter a name and optional description
3. Select the **attribute** to compare (e.g., flavour, allergen group) and click **Apply**
4. The matrix fills with the values that attribute takes across your SKUs - tick the
   allowed pairs, or import them from a spreadsheet
5. Save

## Tips

- Remember pairs are unordered: "A→B" and "B→A" are the same entry
- An empty grid means *nothing* is compatible - every pair must be explicitly allowed
- Keep the rule aligned with the changeover setup: products may be compatible for sharing a
  cycle but still need a changeover between them (see [Changeovers](changeovers))
